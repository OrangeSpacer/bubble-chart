# BubbleChart

Самостоятельный компонент для клиентских React-приложений. Все необходимые исходники и стили находятся в этой папке. Здесь нет зависимости от демо, reducer, начальных данных или глобальных стилей приложения.

## Перенос в другой проект

1. Скопируйте папку `chart` целиком в исходники проекта. Вложенные папки `__tests__` и этот README можно не переносить.
2. Установите совместимые зависимости:

```bash
npm install react@^18 react-dom@^18 react-konva@^18 konva@^9 d3-scale@^4
npm install --save-dev @types/react@^18 @types/react-dom@^18 @types/d3-scale@^4
```

3. Импортируйте компонент и типы из `chart/index.ts`. Стили подключаются самим компонентом; сборщик должен поддерживать импорт CSS и TSX (например, Vite).

```tsx
import { useState } from 'react';
import { BubbleChart, type Bubble } from './chart';

const data: readonly Bubble[] = [
  { id: 1, name: 'Объект A', x: 8, y: 44, size: 60, color: '#2697c1' },
  { id: 2, name: 'Объект B', x: 45, y: 61, size: 35, color: '#d4a034' },
];

export function Example() {
  const [selectedId, setSelectedId] = useState<number>();

  return (
    <BubbleChart
      data={data}
      selectedId={selectedId}
      onSelect={setSelectedId}
      xMode="linear"
      yMode="grouped"
      step={5}
      zones={[
        {
          id: 'high-impact',
          x1: 0,
          x2: 15,
          y1: 40,
          y2: 80,
          color: '#ddeef7',
          title: 'Высокий эффект',
          subtitle: 'Приоритетные объекты',
          titlePosition: { vertical: 'top', horizontal: 'left' },
        },
      ]}
      axisLabels={{ x: 'Стоимость', y: 'Эффект' }}
    />
  );
}
```

Для простого отображения достаточно `<BubbleChart data={data} />`.

## API

| Prop           | Тип                        | По умолчанию / назначение                          |
| -------------- | -------------------------- | -------------------------------------------------- |
| `data`         | `readonly Bubble[]`        | Обязательные данные, не изменяются компонентом     |
| `selectedId`   | `number`                   | Без выделения                                      |
| `activeZoneId` | `string \| number \| null` | `null`, активная зона для приглушения остальных    |
| `onSelect`     | `(id: number) => void`     | Необязательный обработчик клика или касания        |
| `mode`         | `'linear' \| 'grouped'`    | `'grouped'`, общий тип по умолчанию для обеих осей |
| `xMode`        | `'linear' \| 'grouped'`    | Переопределяет `mode` для оси X                    |
| `yMode`        | `'linear' \| 'grouped'`    | Переопределяет `mode` для оси Y                    |
| `step`         | `number`                   | `5`, конечное положительное число                  |
| `labels`       | `boolean`                  | `true`, отображение названий объектов              |
| `zones`        | `readonly ChartZone[]`     | `[]`, произвольное количество зон                  |
| `axisLabels`   | `{ x: string; y: string }` | `{ x: 'X', y: 'Y' }`                               |

`Bubble`: уникальный числовой `id`, строковые `name` и CSS-цвет `color`, конечные числовые `x`, `y`, `size`. `size` — исходное значение из бэка в любых единицах, предварительная нормализация к 100 не требуется. Вызывающий код отвечает за валидацию координат и остальных полей.

Радиус рассчитывается по максимальному положительному конечному `size` в текущем массиве `data`:

```text
radius = 5 + sqrt(size / maxSize) * 23
```

Самый большой объект получает радиус 28 px; например, при `maxSize = 1000` объект с `size = 250` получает 16.5 px. Минимальный радиус — 5 px. Нулевые, отрицательные и нечисловые размеры отображаются минимальным радиусом и не влияют на максимум. Если положительных размеров нет, все радиусы равны 5 px. При изменении набора данных относительные размеры пересчитываются; единственный положительный объект или все одинаковые положительные объекты получают радиус 28 px. Выделение не меняет радиус самого пузырька, только добавляет внешнюю обводку. Слайдер 5–100 остаётся ограничением редактора демо.

## Выбор активной зоны

Выбор управляется извне через `activeZoneId`: строковый или числовой id зоны либо `null`. Без этого prop поведение совпадает с `null`.

```tsx
const data: Bubble[] = [
  { id: 1, name: 'Объект A', x: 8, y: 44, size: 60, color: '#2697c1', zoneId: 'priority' },
  { id: 2, name: 'Объект B', x: 25, y: 30, size: 35, color: '#d4a034', zoneId: 'other' },
  { id: 3, name: 'Без привязки', x: 10, y: 20, size: 20, color: '#c64e6b' },
];

// Выбранная зона и связанные с ней пузырьки сохраняют обычную прозрачность.
<BubbleChart data={data} zones={zones} activeZoneId="priority" />;

// Сброс выбора: все объекты снова имеют обычную прозрачность.
<BubbleChart data={data} zones={zones} activeZoneId={null} />;
```

`Bubble.zoneId?: string | number | null` — необязательная связь с зоной из данных бэка. При активной зоне:

- Остальные зоны приглушаются коэффициентом `opacity=0.25`, включая заливку, границы, title и subtitle.
- Пузырьки с другим `zoneId` также получают этот коэффициент, включая выделение, подпись и соединительную линию.
- Пузырьки без `zoneId`, с `undefined` или `null` сохраняют обычную прозрачность.
- Активная зона и пузырьки с совпадающим `zoneId` сохраняют обычное отображение. Коэффициент умножается на существующую прозрачность, например `0.43` для обычного пузырька.

Идентификаторы сравниваются строго: число `0` и строка `'0'` различаются; `0` и пустая строка являются допустимыми id. Связь для приглушения берётся именно из `zoneId`, а не вычисляется по координатам. Геометрические функции принадлежности зонам и подсчёта объектов продолжают работать по координатам. Выбор активной зоны не меняет данные, шкалы, радиусы, расположение подписей или возможность выбрать пузырёк.

В демо активная зона выбирается кликом по тегу в панели зон; кнопка «Сбросить активную зону» снимает выбор. Reducer демо обрабатывает отдельные действия `{ type: 'select-zone', id }` и `{ type: 'reset-zone' }`. Объект «Отдельный объект» намеренно не имеет `zoneId` и не приглушается. Привязки в примере заданы в данных и не меняются автоматически при перемещении границ зон.

## Контракт зон для бэка

Поле `zones` ответа можно передавать в `<BubbleChart data={data} zones={zones} />`. В проекте нет сервера; пример такого payload формируется в `demo/zones.ts`.

```json
{
  "zones": [
    {
      "id": "priority",
      "x1": 0,
      "x2": 15,
      "y1": 40,
      "y2": 80,
      "color": "#ddeef7",
      "title": "Приоритет",
      "subtitle": "Высокий эффект при низких затратах",
      "titlePosition": { "vertical": "top", "horizontal": "left" },
      "subtitlePosition": { "vertical": "bottom", "horizontal": "right" }
    }
  ]
}
```

- `id` — уникальная строка или число; `color` — CSS-цвет заливки.
- `x1`, `x2`, `y1`, `y2` — конечные числа в единицах данных, не пиксели. Порядок концов интервала может быть обратным: компонент нормализует его. Y растёт вверх.
- `title`, `subtitle` — необязательные строки.
- `titlePosition`, `subtitlePosition` — необязательные объекты `{ vertical: 'top' | 'bottom', horizontal: 'left' | 'right' }`. По умолчанию title находится сверху слева, subtitle наследует его позицию. Если позиции совпадают, title и subtitle образуют блок: title над subtitle, весь блок привязан к указанному углу. Разные позиции размещают подписи независимо.

Зоны ограничиваются видимой областью графика; полностью невидимые, вырожденные и зоны с нечисловыми координатами пропускаются. Подписи привязаны к углам видимой части зоны, обрезаются по её границам, длинные строки сокращаются многоточием. В узких и низких зонах текст может быть скрыт или обрезан. Подписи объектов и сами объекты рисуются поверх зон.

Зоны могут пересекаться, оставлять промежутки и иметь любое количество. Они рисуются в порядке массива; последующие заливки перекрывают предыдущие.

Компонент полностью управляется через props: изменение данных, настроек и выбор объекта сохраняет вызывающее приложение. Ни reducer, ни другой менеджер состояния не требуется.

Для работы со статистикой экспортируются `isPointInZone(point, zone)`, `getZonesForBubble(point, zones)` и `countZones(data, zones)`. Счётчики возвращаются в порядке массива зон. Принадлежность определяется по нормализованным полуоткрытым интервалам `[x1, x2)` и `[y1, y2)`: на общей границе соседних зон объект относится к правой/верхней зоне. Внешние верхняя и правая границы также исключены. При пересечении зон объект учитывается в каждой подходящей зоне; объект вне зон не учитывается. Статистика использует исходные координаты, а не видимую часть прямоугольника.

Это обновление заменяет старый формат `zones={{ cutX, cutY, colors }}` массивом прямоугольников. Старые типы `ZoneOptions`, `ZoneColors` и функция `getZone` удалены; вместо них экспортируются `ChartZone`, `ZoneTextPosition` и функции выше. Слайдеры `cutX/cutY` остаются только в демо и формируют пример массива.

## Файлы

- `index.ts` — публичные экспорты.
- `components/Chart/BubbleChart.tsx` — сборка слоёв Konva.
- `components/Bubble/` — отрисовка пузырьков, подписей и линий; `hooks/useBubbles.ts` готовит позиции, размеры, порядок отрисовки и размещение названий; `utils/` содержит `bubbleSize.ts`, `labelLayout.ts`, `labelText.ts`; `__tests__/` проверяет размеры и размещение.
- `components/Axis/` — сетка, деления и подписи осей; `hooks/useChartAxes.ts` строит независимые X/Y; `utils/axis.ts` содержит алгоритм шкал; `__tests__/axis.test.ts` проверяет его.
- `components/Zone/` — фон, границы и подписи зон; `hooks/useChartZones.ts` готовит прямоугольники и области подписей; `utils/` содержит `zones.ts`, `zoneLabels.ts`, `projectZones.ts`; `__tests__/` проверяет принадлежность зонам и расположение title/subtitle.
- `components/Chart/hooks/useBubbleChart.ts` — связывает хуки осей, пузырьков и зон.
- `components/Chart/utils/geometry.ts` — общая проекция координат и геометрия прямоугольников.
- `components/Chart/utils/zoneFocus.ts` — коэффициент прозрачности по активной зоне.
- `components/Chart/constants/chart.ts` — размеры Canvas и области графика.
- `components/Chart/styles/chart.css` — локальные стили контейнера `.bubble-chart`.
- `components/Chart/__tests__/` — тесты геометрии и интеграции диаграммы.
- `types/index.ts` — контракт данных и props.

Каждая группа содержит свои компоненты и подпапки `hooks`, `utils`, `__tests__`. Компоненты отвечают за отображение, локальные хуки связывают расчёты с React, утилиты выполняют вычисления. Демо использует только публичные экспорты `index.ts` и не входит в зависимости диаграммы.

Canvas имеет размер 760 × 470; на узком контейнере появляется горизонтальная прокрутка. Подключайте компонент на клиенте; серверный рендеринг Canvas не предусмотрен. На расчёт шкал влияют только координаты объектов, границы зон их не меняют.

При `labels=true` названия размещаются автоматически внутри графика. Алгоритм сначала рассматривает позиции вокруг своего пузырька, затем ищет место по сетке всей области. Он учитывает все пузырьки (с запасом для обводки), уже размещённые подписи и прямоугольники title/subtitle зон. Приоритет — меньше пересечений, затем минимальное перекрытие и расстояние от своего пузырька. Длинные подписи размещаются первыми; выбор объекта не меняет расположение подписей.

Текст измеряется Canvas-шрифтом Arial 12 px. Ширина подписи ограничена 200 px; длинное имя сокращается многоточием. Если расстояние от окружности до подписи больше 14 px, рисуется линия от края пузырька к ближайшей точке подписи. Линии рисуются под пузырьками, подписи — поверх них на светлой подложке. `labels=false` отключает и текст, и линии.

Это эвристический алгоритм: при высокой плотности, когда свободного места недостаточно, он выбирает позицию с наименьшим конфликтом. Полное отсутствие пересечений не гарантируется; соединительные линии также могут пересекаться. Положение пересчитывается при изменении данных, шкал и зон.

В режиме Grouped сохраняются начала занятых интервалов, начало и конец шкалы. Пустые интервалы пропускаются полностью, без дополнительного деления на конце предыдущего занятого интервала. Например, X демо при шаге 10 даёт `0 → 10 → 20 → 40+ → 50`: пустое начало интервала `30` отсутствует. `40+` обозначает начало занятого интервала после пропуска; точка `45` находится правее него. Каждый переход между оставшимися делениями занимает одинаковое расстояние, внутри перехода координаты интерполируются. Linear сохраняет все деления. В Grouped пустые интервалы не перечисляются, поэтому большой разрыв между значениями не создаёт большой массив делений.

В исходном проекте `npm run typecheck:chart` отдельно компилирует модуль с `rootDir: src/chart`: импорты исходников из демо или других папок нарушат эту проверку. Тесты шкал и геометрии также используют только файлы внутри `chart`.
