# BubbleChart

Самостоятельный компонент для клиентских React-приложений. Все необходимые исходники и стили находятся в этой папке. Здесь нет зависимости от демо, reducer, начальных данных или глобальных стилей приложения.

## Перенос в другой проект

1. Скопируйте папку `chart` целиком в исходники проекта. Вложенные папки `__tests__` и этот README можно не переносить.
2. Установите совместимые зависимости:

```bash
npm install react@^18 react-dom@^18 react-konva@^18 konva@^9 d3-scale@^4 styled-components@^6
npm install --save-dev @types/react@^18 @types/react-dom@^18 @types/d3-scale@^4
```

3. Импортируйте компонент и типы из `chart/index.ts`. Контейнер оформлен через `styled-components` v6; отдельный CSS-файл подключать не нужно. Типы styled-components включены в пакет.

Компонент принимает `className`, поэтому оформление можно расширять через `styled(BubbleChart)`. Базовый класс `.bubble-chart` сохраняется для настройки компоновки в родительском контейнере. Отрисовка фигур и текста внутри Canvas по-прежнему задаётся параметрами Konva.

```tsx
import { useState } from 'react';
import { BubbleChart, type Bubble } from './chart';

const data: readonly Bubble[] = [
  { id: 1, name: 'Объект A', x: 8, y: 44, size: 60, color: '#2697c1' },
  { id: 2, name: 'Объект B', x: 45, y: 61, size: 35, color: '#d4a034' },
];

export function Example() {
  const [selectedId, setSelectedId] = useState<number>();

  return (
    <BubbleChart
      data={data}
      selectedId={selectedId}
      onSelect={setSelectedId}
      zones={[
        {
          id: 'high-impact',
          x1: 0,
          x2: 15,
          y1: 40,
          y2: 80,
          color: '#ddeef7',
          title: 'Высокий эффект',
          subtitle: 'Приоритетные объекты',
          titlePosition: { vertical: 'top', horizontal: 'left' },
        },
      ]}
      axisSettings={{
        x: { title: 'Стоимость', tickSuffix: ' ₽', mode: 'linear' },
        y: { title: 'Эффект', tickSuffix: '%', mode: 'grouped' },
        step: 5,
        showLines: false,
        autoGap: true,
      }}
    />
  );
}
```

Для простого отображения достаточно `<BubbleChart data={data} />`.

## Размеры и свободное пространство

По умолчанию `axisSettings.autoGap=true`: если пузырёк может обрезаться у края, автоматически добавляется небольшой пиксельный отступ по соответствующей стороне оси. Проверяются все пузырьки с учётом их радиуса, обводки выделения и небольшого запаса для скругления. Стороны, где места хватает, не получают отступ. При изменении данных, размеров или режима осей отступы пересчитываются.

```tsx
<BubbleChart data={data} axisSettings={{ autoGap: true }} />
// Отключение защиты от обрезки:
<BubbleChart data={data} axisSettings={{ autoGap: false }} />
```

Настройку можно менять во время работы; в демо есть переключатель «Автоматические отступы для пузырьков у краёв». Значения делений, числовые диапазоны и правила Grouped сохраняются: меняются только пиксельные позиции точек и делений. Крайние заливки зон заполняют защитный отступ, внутренние границы зон следуют координатам шкал. В контейнере, который физически меньше диаметра пузырька, полностью исключить обрезку невозможно; отступ ограничивается так, чтобы шкала не вырождалась.

Контейнер и сама область данных имеют скругление 8 px. Заливки зон, сетка, пузырьки и соединительные линии обрезаются по скруглённой области; подписи осей снаружи сохраняются.

Диаграмма занимает всю ширину и высоту контейнера. `ResizeObserver` отслеживает его размер, в том числе при изменении размеров панелей и окна. Canvas, шкалы, зоны, позиции пузырьков и подписи пересчитываются под новую область; график не растягивается как готовая картинка, поэтому текст остаётся чётким.

Для заполнения доступной высоты задайте размер родителю:

```tsx
<div style={{ width: '100%', height: 'calc(100dvh - 160px)', minHeight: 280 }}>
  <BubbleChart data={data} zones={zones} />
</div>
```

Либо передайте высоту непосредственно:

```tsx
<BubbleChart data={data} height="70vh" />
<BubbleChart data={data} height={600} />
```

По умолчанию используется `height: 100%` с минимальной высотой 280 px. Если высота родителя не задана, контейнер занимает этот минимум. Размер 760 × 470 используется только до первого измерения. При скрытии контейнера последняя корректная геометрия сохраняется; при появлении измеряется заново. Наблюдение отключается при размонтировании. В браузерах без `ResizeObserver` используется событие изменения размера окна.

В демо нет ограничения ширины страницы, а высота карточки диаграммы рассчитывается по доступной высоте окна с местом для заголовка и панелей управления. Горизонтальная прокрутка для фиксированного Canvas больше не требуется.

## API

Настройки осей сгруппированы в `axisSettings?: AxesSettings`. Типы вынесены в `types/axisSettings.ts` и экспортируются из публичного `chart/index.ts`:

```ts
interface AxisSettings {
  title?: string;
  tickSuffix?: string;
  mode?: 'linear' | 'grouped';
  step?: number;
}

interface AxesSettings {
  x?: AxisSettings;
  y?: AxisSettings;
  mode?: 'linear' | 'grouped';
  step?: number;
  showLines?: boolean;
  autoGap?: boolean;
}
```

Общие `mode` и `step` действуют на обе оси; настройки внутри `x`/`y` переопределяют их независимо. `title` — название, `tickSuffix` — знак деления, `showLines` — ведущие линии, `autoGap` — автоматические отступы. Пустые строки и `false` применяются явно. По умолчанию используются `grouped`, шаг 5, названия X/Y, пустые суффиксы и включённые флаги.

Все настройки осей передаются только через `axisSettings`. Плоские поля осей удалены из `BubbleChartProps`. Медианы остаются отдельным `medianSettings?: MedianSettings`, типы которого находятся в `types/medianSettings.ts`.

| Prop             | Тип                        | По умолчанию / назначение                                                           |
| ---------------- | -------------------------- | ----------------------------------------------------------------------------------- |
| `data`           | `readonly Bubble[]`        | Обязательные данные, не изменяются компонентом                                      |
| `height`         | `CSSProperties['height']`  | Высота контейнера: число в px или CSS-значение; по умолчанию `100%`, минимум 280 px |
| `selectedId`     | `number`                   | Без выделения                                                                       |
| `activeZoneId`   | `string \| number \| null` | `null`, активная зона для приглушения остальных                                     |
| `onSelect`       | `(id: number) => void`     | Необязательный обработчик клика или касания                                         |
| `axisSettings`   | `AxesSettings`             | Общие и независимые настройки осей                                                  |
| `medianSettings` | `MedianSettings`           | Необязательные подписи медиан на границах зон                                       |
| `labels`         | `boolean`                  | `true`, отображение названий объектов                                               |
| `zones`          | `readonly ChartZone[]`     | `[]`, произвольное количество зон                                                   |

`Bubble`: уникальный числовой `id`, строковые `name` и CSS-цвет `color`, конечные числовые `x`, `y`, `size`. `size` — исходное значение из бэка в любых единицах, предварительная нормализация к 100 не требуется. Вызывающий код отвечает за валидацию координат и остальных полей.

Радиус рассчитывается по максимальному положительному конечному `size` в текущем массиве `data`:

```text
radius = 5 + sqrt(size / maxSize) * 23
```

Самый большой объект получает радиус 28 px; например, при `maxSize = 1000` объект с `size = 250` получает 16.5 px. Минимальный радиус — 5 px. Нулевые, отрицательные и нечисловые размеры отображаются минимальным радиусом и не влияют на максимум. Если положительных размеров нет, все радиусы равны 5 px. При изменении набора данных относительные размеры пересчитываются; единственный положительный объект или все одинаковые положительные объекты получают радиус 28 px. Выделение не меняет радиус самого пузырька, только добавляет внешнюю обводку. Слайдер 5–100 остаётся ограничением редактора демо.

## Названия осей и знаки делений

Пунктирные границы зон также не рисуются на внешних краях области графика, независимо от `axisSettings.showLines`. Внутренние границы между зонами сохраняются.

Ведущие линии X и Y можно скрыть через `<BubbleChart data={data} axisSettings={{ showLines: false }} />`. По умолчанию `showLines=true`. Флаг скрывает нижнюю горизонтальную и левую вертикальную линии, включая совпадающие с ними линии сетки. Верхняя и правая границы графика не рисуются при любом значении флага, включая совпадающие с ними линии сетки. Подписи и внутренняя сетка сохраняются; короткие риски делений не рисуются; границы зон управляются самими зонами. В демо есть переключатель «Показывать ведущие линии X и Y».

Названия и единицы задаются независимо для X и Y:

```tsx
<BubbleChart
  data={data}
  axisSettings={{
    x: { title: 'Стоимость', tickSuffix: ' ₽' },
    y: { title: 'Эффект', tickSuffix: '%' },
  }}
/>
```

| Prop                        | Назначение                    | По умолчанию |
| --------------------------- | ----------------------------- | ------------ |
| `axisSettings.x.title`      | Название оси X                | `'X'`        |
| `axisSettings.y.title`      | Название оси Y                | `'Y'`        |
| `axisSettings.x.tickSuffix` | Знак после каждого значения X | `''`         |
| `axisSettings.y.tickSuffix` | Знак после каждого значения Y | `''`         |

Все четыре поля — строки. Например, `%` даёт `10%`, ` ₽` — `10 ₽`, ` шт.` — `10 шт.`. Пробел задаётся в строке явно. Отрицательные значения и маркер Grouped сохраняются: `-10%`, `40+%`. Суффиксы меняют только текст, не значения, шаг, координаты или сжатие интервалов. Названия центрируются вдоль своих осей; длинный текст сокращается многоточием, чтобы не выходить за отведённое место.

При одинаковых начальных значениях и одинаковых единицах осей подпись начала рисуется один раз у пересечения осей: немного левее и ниже угла графика. Например, общий `0` для текущих данных не дублируется на X и Y. Если начала или единицы различаются, подписи сохраняются отдельно. Сетка и геометрия осей не меняются.

Пустая строка `title` скрывает соответствующее название. В демо есть отдельная панель «Подписи осей» с четырьмя полями; общий сброс восстанавливает их исходные значения.

## Медианы

Медианы передаются отдельным необязательным объектом `medianSettings`. Значения приходят извне; компонент не вычисляет медиану из массива объектов.

```tsx
<BubbleChart
  data={data}
  zones={zones}
  medianSettings={{
    x: { value: 15, sign: '%' },
    y: { value: 40, sign: ' ₽' },
  }}
/>
```

```ts
interface MedianAxisSettings {
  value: number;
  sign?: string;
}

interface MedianSettings {
  x?: MedianAxisSettings | null;
  y?: MedianAxisSettings | null;
}
```

`x` добавляет подпись справа от существующей внутренней вертикальной границы зоны, ближе к верхней части графика. `y` добавляет подпись над существующей горизонтальной границей, ближе к правой части графика. Если подходящих границ несколько, выбирается ближайшая к проекции переданного `value`. При перемещении границ подписи следуют за ними; текст значения не меняется. При нехватке места выбирается противоположная сторона. Подписи стараются избегать заголовков зон и друг друга; их области учитываются при размещении названий пузырьков.

Формат подписи — `Медиана {value}{sign}`: `Медиана 15%`, `Медиана 40 ₽`. Знак независим от суффиксов делений осей; пробел задаётся явно. Отдельные линии медиан не рисуются: используются уже существующие пунктирные границы зон. Текст отображается без белой подложки и обводки.

Без `medianSettings` или подходящей внутренней границы зоны медиана не отображается. Можно передать только X или только Y; `null` отключает отдельную медиану. Ноль и отрицательные значения поддерживаются; нечисловые значения пропускаются. `value` задаёт текст и выбор ближайшей границы, но не создаёт новую линию и не расширяет диапазоны. Grouped, адаптивный размер и отступы учитываются через готовую проекцию зон.

Медианы зависят от видимых зон, но не от ведущих линий осей или `activeZoneId`; выбор зоны не приглушает их. В демо есть панель «Медианы», а reducer поддерживает `{ type: 'set-median', axis: 'x' | 'y', settings }`. В публичном API экспортируются типы `MedianSettings` и `MedianAxisSettings`.

## Выбор активной зоны

Выбор управляется извне через `activeZoneId`: строковый или числовой id зоны либо `null`. Без этого prop поведение совпадает с `null`.

```tsx
const data: Bubble[] = [
  { id: 1, name: 'Объект A', x: 8, y: 44, size: 60, color: '#2697c1', zoneId: 'priority' },
  { id: 2, name: 'Объект B', x: 25, y: 30, size: 35, color: '#d4a034', zoneId: 'other' },
  { id: 3, name: 'Без привязки', x: 10, y: 20, size: 20, color: '#c64e6b' },
];

// Выбранная зона и связанные с ней пузырьки сохраняют обычную прозрачность.
<BubbleChart data={data} zones={zones} activeZoneId="priority" />;

// Сброс выбора: все объекты снова имеют обычную прозрачность.
<BubbleChart data={data} zones={zones} activeZoneId={null} />;
```

`Bubble.zoneId?: string | number | null` — необязательная связь с зоной из данных бэка. При активной зоне:

- Остальные зоны приглушаются коэффициентом `opacity=0.25`, включая заливку, границы, title и subtitle.
- Пузырьки с другим `zoneId` также получают этот коэффициент, включая выделение, подпись и соединительную линию.
- Пузырьки без `zoneId`, с `undefined` или `null` также приглушаются. Обычная прозрачность сохраняется только при совпадении с активной зоной.
- Активная зона и пузырьки с совпадающим `zoneId` сохраняют обычное отображение. Коэффициент умножается на существующую прозрачность, например `0.43` для обычного пузырька.

Идентификаторы сравниваются строго: число `0` и строка `'0'` различаются; `0` и пустая строка являются допустимыми id. Связь для приглушения берётся именно из `zoneId`, а не вычисляется по координатам. Геометрические функции принадлежности зонам и подсчёта объектов продолжают работать по координатам. Выбор активной зоны не меняет данные, шкалы, радиусы, расположение подписей или возможность выбрать пузырёк.

В демо активная зона выбирается кликом по тегу в панели зон; кнопка «Сбросить активную зону» снимает выбор. Reducer демо обрабатывает отдельные действия `{ type: 'select-zone', id }` и `{ type: 'reset-zone' }`. Объект «Отдельный объект» не имеет `zoneId` и приглушается при выборе любой зоны. При сбросе выбора все объекты получают обычную прозрачность. Привязки в примере заданы в данных и не меняются автоматически при перемещении границ зон.

## Контракт зон для бэка

Поле `zones` ответа можно передавать в `<BubbleChart data={data} zones={zones} />`. В проекте нет сервера; пример такого payload формируется в `demo/zones.ts`.

```json
{
  "zones": [
    {
      "id": "priority",
      "x1": 0,
      "x2": 15,
      "y1": 40,
      "y2": 80,
      "color": "#ddeef7",
      "title": "Приоритет",
      "subtitle": "Высокий эффект при низких затратах",
      "titlePosition": { "vertical": "top", "horizontal": "left" },
      "subtitlePosition": { "vertical": "bottom", "horizontal": "right" }
    }
  ]
}
```

- `id` — уникальная строка или число; `color` — CSS-цвет заливки.
- `x1`, `x2`, `y1`, `y2` — конечные числа в единицах данных, не пиксели. Порядок концов интервала может быть обратным: компонент нормализует его. Y растёт вверх.
- `title`, `subtitle` — необязательные строки.
- `titlePosition`, `subtitlePosition` — необязательные объекты `{ vertical: 'top' | 'bottom', horizontal: 'left' | 'right' }`. По умолчанию title находится сверху слева, subtitle наследует его позицию. Если позиции совпадают, title и subtitle образуют блок: title над subtitle, весь блок привязан к указанному углу. Разные позиции размещают подписи независимо.

Зоны ограничиваются видимой областью графика; полностью невидимые, вырожденные и зоны с нечисловыми координатами пропускаются. Подписи привязаны к углам видимой части зоны, обрезаются по её границам, длинные строки сокращаются многоточием. В узких и низких зонах текст может быть скрыт или обрезан. Подписи объектов и сами объекты рисуются поверх зон.

Зоны могут пересекаться, оставлять промежутки и иметь любое количество. Они рисуются в порядке массива; последующие заливки перекрывают предыдущие.

Компонент полностью управляется через props: изменение данных, настроек и выбор объекта сохраняет вызывающее приложение. Ни reducer, ни другой менеджер состояния не требуется.

Для работы со статистикой экспортируются `isPointInZone(point, zone)`, `getZonesForBubble(point, zones)` и `countZones(data, zones)`. Счётчики возвращаются в порядке массива зон. Принадлежность определяется по нормализованным полуоткрытым интервалам `[x1, x2)` и `[y1, y2)`: на общей границе соседних зон объект относится к правой/верхней зоне. Внешние верхняя и правая границы также исключены. При пересечении зон объект учитывается в каждой подходящей зоне; объект вне зон не учитывается. Статистика использует исходные координаты, а не видимую часть прямоугольника.

Это обновление заменяет старый формат `zones={{ cutX, cutY, colors }}` массивом прямоугольников. Старые типы `ZoneOptions`, `ZoneColors` и функция `getZone` удалены; вместо них экспортируются `ChartZone`, `ZoneTextPosition` и функции выше. Слайдеры `cutX/cutY` остаются только в демо и формируют пример массива.

- `components/Axis/` — сетка, деления и подписи осей; `hooks/useChartAxes.ts` строит независимые X/Y; `utils/axis.ts` содержит алгоритм шкал; `__tests__/axis.test.ts` проверяет его.

- `components/Chart/__tests__/` — тесты геометрии и интеграции диаграммы.

Каждая группа содержит свои компоненты и подпапки `hooks`, `utils`, `__tests__`. Компоненты отвечают за отображение, локальные хуки связывают расчёты с React, утилиты выполняют вычисления. Демо использует только публичные экспорты `index.ts` и не входит в зависимости диаграммы.

Подключайте компонент на клиенте; серверный рендеринг Canvas не предусмотрен. На расчёт числовых диапазонов шкал влияют только координаты объектов, границы зон их не меняют. Пиксельные размеры шкал зависят от контейнера.

При `labels=true` названия размещаются автоматически внутри графика. Алгоритм сначала рассматривает позиции вокруг своего пузырька, затем ищет место по сетке всей области. Он учитывает все пузырьки (с запасом для обводки), уже размещённые подписи и прямоугольники title/subtitle зон. Приоритет — меньше пересечений, затем минимальное перекрытие и расстояние от своего пузырька. Длинные подписи размещаются первыми; выбор объекта не меняет расположение подписей.

Текст измеряется Canvas-шрифтом Arial 12 px. Ширина подписи ограничена 200 px; длинное имя сокращается многоточием. Если расстояние от окружности до подписи больше 14 px, рисуется линия от края пузырька к ближайшей точке подписи. Линии рисуются под пузырьками, подписи — поверх них на светлой подложке. `labels=false` отключает и текст, и линии.

Это эвристический алгоритм: при высокой плотности, когда свободного места недостаточно, он выбирает позицию с наименьшим конфликтом. Полное отсутствие пересечений не гарантируется; соединительные линии также могут пересекаться. Положение пересчитывается при изменении данных, шкал и зон.

В режиме Grouped сохраняются начала занятых интервалов, начало и конец шкалы. Пустые интервалы пропускаются полностью, без дополнительного деления на конце предыдущего занятого интервала. Например, X демо при шаге 10 даёт `0 → 10 → 20 → 40+ → 50`: пустое начало интервала `30` отсутствует. `40+` обозначает начало занятого интервала после пропуска; точка `45` находится правее него. Каждый переход между оставшимися делениями занимает одинаковое расстояние, внутри перехода координаты интерполируются. Linear сохраняет все деления. В Grouped пустые интервалы не перечисляются, поэтому большой разрыв между значениями не создаёт большой массив делений.

Конечная граница сразу после последнего деления с `+` не рисуется. В примере выше видимые деления — `0 → 10 → 20 → 40+`, а `50` остаётся служебной границей для интерполяции. Благодаря этому точка `45` по-прежнему находится правее `40+`, а координаты зон и пузырьков не меняются. Если последняя группа не начинается с `+`, её конечное деление сохраняется; Linear не затрагивается.

В исходном проекте `npm run typecheck:chart` отдельно компилирует модуль с `rootDir: src/chart`: импорты исходников из демо или других папок нарушат эту проверку. Тесты шкал и геометрии также используют только файлы внутри `chart`.
